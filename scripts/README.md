# Member B training scripts

These scripts train and use the optional `LearnedMotionPredictor` described
in proposal §3.5 ("learned sketch-conditioned motion predictor").

## Environment

On macOS with Apple Silicon (recommended for the M-series GPU via MPS):

```bash
python -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install numpy opencv-python pillow pyyaml scipy scikit-image \
            torch torchvision transformers tqdm
```

`torch` on Apple Silicon ships with MPS support out of the box. Set
`PYTORCH_ENABLE_MPS_FALLBACK=1` so unsupported ops automatically fall back to
the CPU instead of erroring out:

```bash
export PYTORCH_ENABLE_MPS_FALLBACK=1
```

## 1. Quick smoke test (synthetic data, ~10 min on M4 Max)

Trains the U-Net for a handful of epochs on procedurally generated
landscape pairs to verify the end-to-end training pipeline.

```bash
python scripts/train_learned_predictor.py \
    --epochs 5 \
    --num-samples 256 \
    --batch-size 8
```

Checkpoints land under `checkpoints/`:

- `checkpoints/best.pt` — lowest validation loss seen so far
- `checkpoints/last.pt` — most recent epoch

## 2. Longer synthetic training (~1-2 hours on M4 Max)

```bash
python scripts/train_learned_predictor.py \
    --epochs 50 \
    --num-samples 4000 \
    --batch-size 8
```

## 3. Real-data preparation (one-off, ~few hours depending on dataset size)

`scripts/prepare_dataset.py` converts a folder of landscape videos into
`(image, sketch, mask, flow)` training tuples. RAFT (small variant from
`torchvision.models.optical_flow`) is used for the flow; the mask is
generated by reusing the project's Grounded-SAM backend so the training
distribution matches inference.

```bash
python scripts/prepare_dataset.py \
    --videos data/raw/landscape/*.mp4 \
    --output data/training/landscape \
    --prompt "water. river. sea. waterfall." \
    --frame-stride 5 \
    --max-pairs-per-video 6 \
    --image-size 384
```

For the validation split, repeat the command on a held-out video folder:

```bash
python scripts/prepare_dataset.py \
    --videos data/raw/landscape_val/*.mp4 \
    --output data/training/landscape_val \
    ...
```

Recommended source dataset: the landscape collection accompanying
*Animating Pictures with Eulerian Motion Fields* (Holynski et al., CVPR
2021), available from <https://eulerian.cs.washington.edu/>.

## 4. Real-data training (~1-2 days on M4 Max)

```bash
python scripts/train_learned_predictor.py \
    --data-root data/training/landscape \
    --val-data-root data/training/landscape_val \
    --epochs 80 \
    --batch-size 8 \
    --image-size 256 \
    --learning-rate 1e-4
```

## 5. Plug the trained model into the pipeline

Update your config file (e.g. `configs/default.yaml`) to wire the
checkpoint into the learned predictor and let `pipeline.py` opt in:

```yaml
motion:
  backend: learned          # or 'heuristic' (default)
  learned:
    checkpoint_path: checkpoints/best.pt
    device: mps             # 'cuda', 'mps' or 'cpu'
    input_size: 256
    base_channels: 64
```

Then in code (or in a wrapper script):

```python
from src.motion_field.learned_predictor import LearnedMotionPredictor

predictor = LearnedMotionPredictor(cfg["motion"]["learned"])
flow = predictor.predict(reference_image, fluid_mask, motion_sketch)
```

The predicted flow is the same `H x W x 2 float32` array the heuristic
pipeline produces, so it can be dropped straight into
`smooth_motion_field` and the rest of the synthesis pipeline.

## Tips & troubleshooting

- **MPS out of memory** — reduce `--batch-size` or `--image-size`.
- **MPS op not implemented** — make sure `PYTORCH_ENABLE_MPS_FALLBACK=1`
  is set in the same shell that launches training.
- **Loss explodes early** — lower `--learning-rate` to `5e-5`, or scale
  ground-truth flows down with `--flow-scale 0.5`.
- **Slower than expected on M4 Max** — open Activity Monitor; if the GPU
  utilisation stays below ~30 % you may be data-bound. Increase
  `--num-workers` (e.g. 4) or pre-resize the dataset to the training
  resolution to skip per-iteration `cv2.resize`.
